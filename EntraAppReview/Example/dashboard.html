Entra application triage

DEMONSTRATION DATA ONLY - this report does not contain a real tenant inventory.
Scope, ranking model, and important limitations

This inventory combines local app registrations and tenant service principals, including managed identities and Microsoft/third-party enterprise apps. A registration is linked by client ID; registrations without a service principal are retained. Disabled apps remain visible and retain their grant-based score.

Priority is a heuristic, not an effective-access calculation. Only granted API permissions contribute: maximum permission weight plus one point per additional distinct resource/type/permission, capped at +5 and a total of 100. Application permissions are not user-bound; delegated access is limited by the signed-in user and API policy. Repeated per-user consent does not inflate the score.

Microsoft Graph weights: identity/credential/consent control 95; broad write/full control/mail sending 80; broad read 65; selected-resource scopes 40; basic sign-in scopes 20; unclassified scopes 60. Delegated weights are reduced by 15, minimum 5. Non-Graph APIs are conservatively 70 and unresolved grants 75, both requiring manual review; the default/zero app role is 10. Critical ≥90, High ≥65, Medium ≥35, Low >0. Zero means no collected API grants, not no access.

Requested permissions are displayed separately and never treated as consent. Existing grants can exceed a registration's current request list. Tenant-wide and per-user delegated consents are distinguished; principal IDs are preserved without looking up user profiles.

Secret expiration is a separate operational signal, not privilege. UTC dates and days remaining are calculated at collection start. Metadata only: secret values and hints are never exported. For external/multitenant apps, home-tenant registration secrets are not visible here. A managed identity normally has no client secret.

This is not a point-in-time transactional snapshot. Entra replication and changes during collection can affect results. Not covered: Entra directory roles/PIM, Azure RBAC, Exchange application RBAC/access policies, SharePoint or Teams resource-specific grants, API-internal authorization, federated credentials, certificates, or secrets outside Entra. No tenant changes or external network requests are made by this dashboard.
